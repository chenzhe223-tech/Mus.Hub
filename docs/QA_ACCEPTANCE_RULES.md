# Mus.Hub（音画 · SONIC ARCHIVE）上线验收标准与 QA 门禁规则

> **原则：任何改动在“验收规则”全部通过前，严禁交付上线；修复 A 功能时，必须对 B/C/D 核心功能执行交叉回归，杜绝“修好一处、搞坏另一处”。**

---

| **P0-7** | **边缘接口与缓存安全** | 1) `/api/health` 返回 200；<br>2) `/api/proxy` 拦截非白名单域名（返回 403，防 SSRF）且支持音频 `Range` / `206` 与 `no-transform`；<br>3) `/api/preview` 缺参返回 400、有效参数流式返回非过期原曲；<br>4) 每次音频/搜索逻辑变更必须升级 `EDGE_CACHE_VERSION` 清空旧缓存。 | 自动化接口冒烟测试 |

## 二、P1 体验级检查项（每次发版逐项核对）

1. **真实歌词提取**：选择华语/欧美热门歌曲后，可提取真实歌词并点击上墙，不出现乱码或作词作曲元数据污染。
2. **扫码分享落地页**：点击「预览好友视角」或扫码打开，可正常渲染同款海报、播放当前歌曲原曲、点击 4 大外部音乐平台（网易云/QQ音乐/Apple Music/Spotify）跳转准确。
3. **听歌识曲与 AI 声纹入口**：弹窗正常开关、录音/上传交互不报错、未配置云端密钥时状态提示清晰友好。
4. **社交唱片墙与草稿箱**：存草稿、上架唱片墙、点赞评论、加载同款版式功能正常且刷新后数据保留。

## 三、强制执行流程（QA 门禁闭环）

每次改代码后、交付给你之前，必须严格执行以下 4 步并输出**验收报告**：

1. **改前影响面评估**：明确本次改动会触及哪些模块（例如改音频引擎必测「桌面播放 + 手机播放 + 有声视频录制」三项联动）。
2. **自动化 QA 一键门禁（`npm run qa`）**：
   - TypeScript 全量类型检查 (`tsc -b`)
   - 生产构建 (`vite build`)
   - 自动化单测（中文归一化、严格歌名防串歌、音频候选生成、视频录制音轨绑定校验）
   - 本地 Preview 接口冒烟测试（`/`、`/api/health`、`/api/proxy` SSRF 拦截、`/api/preview`、`/api/recognize/status`、`/api/ai-song/status`、`/api/ai-song/lyrics`）
   - Cloudflare Workers 预打包校验 (`wrangler deploy --dry-run`)
3. **交叉回归清单自检**：逐项列出 P0-1 至 P0-7 的实测状态，**区分「自动化已通过」与「需手机真机复核」**，绝不口头保证未测项。
4. **通过后方可交付部署**：全部 P0 项绿灯后，才通知你执行 `一键推送GitHub并上线.bat`，并附上一份 30 秒真机快速验收清单。
